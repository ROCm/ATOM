Q1: The K2a selection helper _selected_rows (index_score.py:330) changes only the address of its speculative candidate-table load: old `t*TOPK_BLOCKS + fx.max(ident,0)//TILE` used ident directly, so on FULL layers, where ident is a history row ID (up to context length), the prefetch ran past token t's 2048-slot row of the tokens*2048-element icand buffer (token 35 / ident 316436 read element 111234 of a 73728-element allocation); the new shared pure function index_plan.candidate_offset(t, ident) = i32(t*TOPK_BLOCKS + imin(imax(ident,0)//BLOCK_ROWS, TOPK_BLOCKS-1)) clamps the slot into [0, TOPK_BLOCKS-1] so every speculative load lands inside token t's own row. The clamped value is used for nothing else: lifted = cand*TILE + max(ident,0)%TILE and row = (ilift!=0 & ident>=0) ? lifted : ident are untouched, so live REINDEX columns (< TOPK_BLOCKS*BLOCK_ROWS = 16384) keep their exact candidate slot and FULL/padding keep their original selected row while discarding the candidate value.
