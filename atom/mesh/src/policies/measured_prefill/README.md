# Measured prefill cost kernel

This is an experimental decision kernel, not an enabled router policy. It is
based on the 900-second 128c capture at `80b85aa` (24,150.15 aligned tok/s/GPU,
93.0238% token-weighted cache hit). The capture is the accepted observation
baseline; this change has no measured throughput result of its own.

For each possible placement, replay the currently unfinished prefills under
the backend's chunk/checkpoint geometry. One synchronized DP step has one
cycle cost, estimated from global/max query tokens and query-context work.
The objective is the sum of completion times of all unfinished prefills:

`J = sum_over_steps(unfinished_request_count * predicted_DP_cycle_seconds)`

Switch only if the destination improves both J and the incoming request's
completion time after applying the empirical cycle residual guard. This counts
the delay that extra cold-cache work imposes on other ranks. It does not use
per-concurrency absolute/relative load thresholds or a migration quota.

The model coefficients and residual are inputs. The captured-runtime example
is in `fixtures-provenance.json`; its residual is the absolute cycle error P90
on the middle 20% calibration segment. It is neither a universal model nor a
simultaneous/counterfactual confidence bound. The last 20% was inspected while
diagnosing a checkpoint-rule error and is no longer an untouched blind test.

The measured V4 backend declares `StateTransfer.copy`. Its PAGE coordinator's
successor room is zero. The block-manager comment about a V4 fork room of 131
describes an older implementation; callers must use actual backend geometry.

## Integration contract

`Evidence::default()` abstains. A production adapter must establish all of:

- A coherent, fresh snapshot of every rank, with successful chunk progress and
  stable request/attempt identity. Completed prefill work leaves the ledger at
  prefill completion, not at the end of decode.
- Resident-cache probes for backlog and candidate placements. A historical
  text-prefix match or a later admission's cache hit is not a live probe.
- Explicit treatment of capacity/allocation/connector stalls and in-flight
  reservations. Truncated or unsupported state must not authorize a switch.
- Runtime-matching calibration and feature-domain checks for every placement.

The caller serializes snapshot, decision, and reservation. A reservation seen
in an engine snapshot replaces its local pending entry rather than being
counted twice. Retries and cancellation require distinct attempt identities.
If the kernel returns an error or insufficient evidence, preserve healthy
affinity; health/failover handling remains the caller's responsibility.

The kernel models current backlog and prefill completion boundaries. It does
not predict future arrivals, client TTFT, decode latency, cache eviction caused
by alternate schedules, or throughput. Cache/progress transport is not part of
this change, so it must not replace the current policy in a performance run.

## Validation

`cargo test --lib policies::measured_prefill::` checks independent completion
arithmetic, beneficial cold placement, harmful externalities, residual guards,
missing evidence, token progress, duplicate jobs, finite horizons and input
immutability. It also checks 5,000 cases generated by executing the captured
scheduler's actual arithmetic and 130 factual DP snapshots against the Python
reference. The latter deliberately use oracle admission cache; they validate
implementation parity, not online decisions or performance.

Fixtures contain only numeric workload geometry. `fixtures-provenance.json`
records source/archive hashes and the temporal fit split.
